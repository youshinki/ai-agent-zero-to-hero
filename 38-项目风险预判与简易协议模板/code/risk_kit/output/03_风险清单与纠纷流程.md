# 项目风险清单与应对

## 需求理解不一致（高）
- 成因：口头承诺、需求描述模糊
- 应对：开发前文字确认功能清单，双方回复确认

## 需求无限新增（高）
- 成因：客户开发中持续加想法
- 应对：约定需求变更规则，新增功能单独评估报价

## 尾款拖欠（高）
- 成因：未约定付款节点与违约责任
- 应对：预付50%+验收结清尾款，协议写明节点

## 文档素材延期（中）
- 成因：客户迟迟不提供资料，导致延期
- 应对：约定素材提供时限，延迟则交付顺延

## 部署环境兼容（中）
- 成因：客户环境老旧、缺依赖
- 应对：约定测试环境可用；特殊环境适配另行报价

## 售后边界模糊（高）
- 成因：把新增功能/API欠费算作BUG
- 应对：明确免费售后范围与有偿服务边界


# 纠纷处理流程

1. **核对依据**：调取双方确认的需求清单与协议原文，核对争议点是否在约定交付范围内
2. **分类处理**：属于BUG → 免费修复；属于新增需求 → 单独报价，双方确认后开发
3. **书面留痕**：所有沟通通过文字进行，截图保存聊天记录与确认信息
4. **冷静沟通**：不与客户争辩技术优劣，用演示与文档说话
5. **终止机制**：无法协商时，按已完成工作量结算，签署终止协议，交付已完成部分
